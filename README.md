# AI 智囊团：需求分析与设计过程

AI 智囊团是面向移动端的 HTML5 课程设计，使用 Vue 3、TypeScript 和 Vite，将多角色对话、个人资料问答、本地数据预测、双角色对辩、猜心互动与记忆管理整合在同一应用中。项目包含浏览器应用、PWA 基础能力及 Capacitor Android 工程。

应用以统一的主题、导航、卡片、状态反馈和移动端布局组织各项功能。本文介绍项目需求、总体架构、数据设计、核心实现与界面设计过程。

## 1. 项目背景与目标

### 1.1 背景分析

通用聊天界面需要用户自行组织问题，面对空白输入框时不容易确定从哪里开始。课程学习与日常使用还涉及按领域请教、导入自己的资料、对数字进行分析、比较不同观点以及重新查找历史记录等需求。

项目采用“按任务组织入口”的思路：想找人聊时选择角色，想查资料时进入知识库，想分析数据时进入预测页。不同场景共享模型通信、会话管理和本地存储，减少重复操作。

### 1.2 建设目标

1. 降低提问门槛：提供通用助手、分类角色、自建角色和临时人设。
2. 连接个人资料：支持文本、TXT、带文本层的 PDF，回答可查看引用出处。
3. 展示本地计算：在浏览器内完成数值预处理、模型训练、评估和预测。
4. 组织多轮互动：通过流程和状态约束支撑对辩、猜心、停止、重试与恢复。
5. 延续使用过程：在本机保存会话、资料、记忆和设置。
6. 适配移动使用：统一触屏交互、窄屏布局及 Android 容器体验。

### 1.3 系统边界

项目以前端为主体，没有自建账号服务、业务数据库服务器和模型推理服务器。生成内容时，客户端请求用户配置的模型接口；问数使用 TensorFlow.js 在设备本地运行。

“本地保存”指记录保存在当前浏览器或应用的数据空间中。模型请求仍会向配置的服务发送问题及必要的历史、记忆或资料片段，因此不能将整个应用描述为全程离线。没有实现云端账号同步。

## 2. 需求分析

### 2.1 目标场景

| 场景 | 用户操作 | 预期结果 |
| --- | --- | --- |
| 快速问答 | 首页直接输入问题 | 无需选择角色即可开聊 |
| 领域交流 | 找数学老师、工程师或产品经理 | 根据角色身份组织回答 |
| 资料学习 | 导入课程材料，提出问题并连续追问 | 按相关片段回答，可查看出处 |
| 趋势分析 | 粘贴数列或导入 CSV | 本地训练并展示预测和误差 |
| 观点比较 | 为两个角色设置同一议题 | 从正反立场轮流讨论 |
| 猜心互动 | 想好对象，回答是/否/不确定 | 逐轮提问，用户确认候选 |
| 记录管理 | 搜索历史、查看记忆、修改设置 | 继续使用已有信息并保持可管理 |

### 2.2 功能需求

| 模块 | 具体需求 | 关键约束 |
| --- | --- | --- |
| 首页与角色 | 快速开聊、最近会话、分类、搜索、自建与临时角色 | 统一解析角色标识 |
| 聊天 | 流式回复、停止、重试、分页、会话切换、跨会话搜索、长图导出 | 旧请求不能污染新会话 |
| 问知 | 文本/TXT/PDF 导入、分块、检索、指定资料提问、引用和删除 | 引用对应本轮真实片段 |
| 问数 | CSV 预览、列选择、参数配置、训练、停止、预测、图表与回测 | 训练和测试按时间区分 |
| 问理 | 角色与议题选择、正反方交替发言、停止和继续 | 明确立场并保留对话历史 |
| 猜心 | 单问交互、三种回答、候选确认、猜错继续、撤回、暂停、重试和记录 | 结构校验与状态转换一致 |
| 记忆 | 抽取、合并、查看、删除、启停和导出 | 不完整回复及猜心不污染记忆 |
| 设置 | 厂商预设、密钥、高级配置、连接测试、主题和 PIN 锁 | 用户自行配置，不在源码放密钥 |
| 应用封装 | 静态缓存、Android 容器、返回键和系统栏适配 | 复用同一套前端代码 |

### 2.3 非功能需求

- **性能**：流式文本按帧合并更新，历史按页读取，大列表使用虚拟滚动，训练优先放入 Worker，较大依赖拆包。
- **可靠性**：区分加载、完成、中断和错误；切换会话或修改预测参数后，过期任务不得覆盖新状态。
- **移动端**：考虑安全区、软键盘、横竖屏、系统字号、窄屏和触屏反馈。
- **安全**：Markdown 经过净化，PIN 保存哈希，资料内容作为数据处理，敏感配置不写入仓库。
- **维护**：页面、状态、通信、算法及存储分层，核心规则可独立测试。

## 3. 总体设计

### 3.1 技术选型

| 层次 | 技术 | 设计理由 |
| --- | --- | --- |
| 页面 | Vue 3、Composition API | 组织组件并复用响应式交互 |
| 类型 | TypeScript | 明确消息、角色、资料和预测结果契约 |
| 状态与路由 | Pinia、Vue Router Hash 模式 | 共享业务状态，减少静态托管路由重写要求 |
| 构建 | Vite、pnpm | 开发调试、依赖管理、生产构建 |
| 数据 | IndexedDB、localStorage | 保存结构化记录及少量同步读取的主题配置 |
| 通信 | Fetch、ReadableStream、SSE | 增量输出、超时、中断和错误处理 |
| 正文 | marked、DOMPurify | Markdown 转换及 HTML 净化 |
| 文档 | PDF.js | 提取 PDF 文本层 |
| 计算 | TensorFlow.js、Web Worker | 设备端训练并减轻主线程压力 |
| 图表与导出 | Canvas、Web Share API | 绘图、生成长图及按环境分享或下载 |
| 封装 | Capacitor、Android Gradle 工程 | 将网页构建产物装入原生容器 |
| 质量 | Vitest、vue-tsc、ESLint、Prettier | 规则验证、类型检查及代码规范 |

版本范围见 [package.json](package.json)，依赖解析由 `pnpm-lock.yaml` 记录。

### 3.2 分层结构

```text
页面与组件：views / components
             ↓
状态和流程：stores / composables
             ↓
模型通信 api / 提示词 prompt / 检索 rag / 预测 ml
             ↓
本地数据访问 db / 浏览器能力

外部服务：用户配置的模型接口
运行环境：浏览器 / PWA / Capacitor Android
```

页面负责输入与呈现，Store 负责异步流程和业务状态，独立模块实现算法与接口。视觉调整不必同时修改预测算法，检索规则变化也无需重写整个聊天页。

### 3.3 页面结构

| 路由 | 职责 |
| --- | --- |
| `/` | 首页、快速开聊与功能入口 |
| `/personas`、`/personas/edit` | 角色查找和编辑 |
| `/chat` | 消息、引用及会话操作 |
| `/library` | 资料管理与检索 |
| `/predict` | 数值输入、训练与结果解释 |
| `/debate` | 双角色对辩 |
| `/guess` | 猜心对局及历史 |
| `/memories` | 长期记忆管理 |
| `/me` | 接口、主题和隐私设置 |

页面按需加载。Android 返回键在子页面优先回退路由，在首页可退出应用。

## 4. 数据设计

### 4.1 对象仓库

IndexedDB 当前版本为 2，主要结构如下。

| 仓库 | 内容 | 关联 |
| --- | --- | --- |
| `sessions` | 会话标题、角色、资料范围、时间 | 一条会话对应多条消息 |
| `messages` | 正文、角色、状态、引用、时间 | `sessionId` 对应会话 |
| `memories` | 用户事实、主题、权重、更新时间 | 后续适用对话的长期信息 |
| `documents` | 资料元数据和正文 | 一份资料对应多个分块 |
| `chunks` | 片段、位置、文档关联 | 检索及引用定位 |
| `kv` | 配置、自建角色、隐私、对局等 | 零散键值记录 |

主题存入 localStorage，启动时同步读取，在挂载前应用，减少主题闪烁。业务记录使用 IndexedDB 异步访问。

### 4.2 一致性与数据规模

消息按会话和时间的复合索引分页读取；正文搜索用游标扫描并限制扫描数与命中数。写入前将响应式 Proxy 转为普通对象，避免结构化克隆错误。需要一起提交的写入使用事务，提交后才报告成功。

预测输入和结果保留在当前运行会话的 Store 中，切换页面可以延续，重启后不保证恢复，不能将其描述为持久化预测档案。不同浏览器和应用的数据空间相互独立，卸载或清除站点数据可能丢失记录。

## 5. 核心模块实现设计

### 5.1 多角色与流式对话

角色使用身份、性格、表达方式、知识边界、禁忌等字段组织。内置、自建、临时角色统一解析，历史会话保存角色标识，避免自建角色被当成默认助手。

请求链路：确认会话和配置 → 选择记忆与资料 → 组装 system 和历史 → 发起流式请求 → 解析 SSE → 按帧写入文本 → 渲染并持久化。

SSE 必须处理网络分包、换行、结束标识及尾部残留，不能假定一次读取恰好对应一条事件。停止通过 AbortController 实现。Markdown 经 marked 解析、DOMPurify 净化后展示。

会话切换和异步分页采用版本标识，过期结果不能覆盖当前会话。失败、主动停止或截断的回答标记为不完整：保留已显示内容，但不当作完整历史继续发送，也不抽取长期记忆。历史裁剪保留完整问答轮次及当前问题。

### 5.2 问知：资料处理与引用

```text
文本 / TXT / PDF 文本层
→ 正文提取与分块
→ 本地保存
→ 按问题检索
→ 合并片段并分配本轮引用编号
→ 模型回答
→ 查看出处与原文
```

当前搜索主路径是关键词匹配。原问题命中较弱且已配置对话接口时，可请求模型提取检索词，再合并关键词结果；提取失败时保留原问题结果。它是检索增强，不是用资料训练大模型。

代码保留余弦相似度、向量搜索函数和 Embedding 配置类型，但当前 `stores/rag.ts` 主搜索流程没有调用 Embedding。设置界面也以对话配置为主，不能据此宣称已接通向量问答或使用向量数据库。

短追问会补入最近明确的用户主题和必要问题链；明确的新问题独立检索，避免旧话题混入。指定文档范围随会话保存，恢复和重试沿用对应范围。

引用使用本轮实际片段编号，历史回答不能成为新证据。当前指定资料问答允许在资料不足时补充模型知识，但要求区分来源并追加核实提示，不能将补充内容伪装成文档事实。

PDF 解析依赖文本层，不含 OCR。扫描件、复杂表格和跨栏排版可能提取不完整，必要时检查原文或粘贴整理后的文本。

### 5.3 问数：本地时间序列预测

用户粘贴数列或导入 CSV，选择列、窗口长度、预测步数和训练轮数，并可设置采样周期与数值单位。CSV 逐字符解析，考虑引号内逗号、换行、转义、BOM 和不齐整行；预览使用虚拟滚动。

计算过程：

1. 检查数值有效性及样本数量。
2. 按时间顺序切分训练段和留出测试段。
3. 只用训练段估计 min/max，避免测试数据参与缩放器拟合。
4. 用滑动窗口构建输入与下一步标签。
5. 优先在 Web Worker 中使用 TensorFlow.js 训练。
6. 在留出段计算指标，进行多步滚动回测。
7. 与“未来保持最后一个已知值”的基线比较。
8. 评估结束后，用全历史窗口短暂微调，再递推未来结果。
9. 用 Canvas 曲线、指标、逐期数值和趋势说明展示结果。

采用多层全连接网络，包含 Dropout、ReLU 和单数值输出，优化器为 Adam，损失为均方误差；训练包含无明显改进时停止的处理，常量序列有独立路径。

展示 RMSE、MAE、MAPE、R²，并区分训练与测试指标。滚动回测允许各起点使用当时已知历史，相邻预测区间重叠，因此误差对数不等于独立样本数量。

修改数据或参数会使旧结果失效，取消和任务标识防止旧结果覆盖新输入。预测是基于历史的实验性外推，不能保证现实未来按曲线变化。

### 5.4 问理：双角色对辩

用户选择角色和议题，系统明确分配正反立场，轮流请求发言并带入对方近期观点。人设决定表达特点，额外立场约束决定论证方向，不能只靠角色名字假设其支持哪一方。

发言长度通过提示词控制，便于手机阅读；支持停止、继续和重置。对辩呈现观点，不构成事实核验，也没有实现客观裁判。

### 5.5 猜心：多轮状态机

用户心里确定对象，逐轮回答“是、否、不确定”。模型负责提问与推理，客户端负责解析、校验、状态转换和操作控制。当前 `MAX_ROUNDS = 60`，历史最多保留 20 局。

状态包括未开始、请求中、等待回答、候选确认、错误、猜中和结束。重点约束如下：

- 每轮一个可回答的问题，避免同时确认多个条件。
- 区分明确否定和未知信息，不把“不确定”当作反证。
- 猜错后记录候选与别名，继续收敛，避免反复猜同一对象。
- 支持撤回、暂停、重试、放弃、恢复及历史回看。
- 游戏内容不直接写入用户长期记忆。

轮数上限是流程限制，不是必能猜中的承诺；猜中由用户确认。

### 5.6 长期记忆与隐私

完整对话可触发模型抽取值得长期保留的用户事实，再进行合并、权重和时间衰减管理。用户可以查看、删除、启停和导出。

历史保存原始交流，记忆保存精炼事实，两者分开。指定资料问答不应以记忆代替文档证据，不完整回复及猜心内容不应污染记忆。

PIN 使用哈希校验，是界面的访问限制，并不加密整个 IndexedDB。API Key 在本机配置，在请求时发送到所选接口服务，不能解释为密钥永不离开设备。

## 6. 设计过程与界面设计

### 6.1 从场景建立信息结构

先明确各场景的输入和输出，再组织首页入口、业务页面和管理页面。用户按照任务进入功能，再提供问题、资料或数字；通用能力由底层共享。

### 6.2 业务流程与异常处理设计

以页面、通信和存储为基础，连接角色、资料、记忆与本地预测。多轮流程同时考虑停止、重试、会话切换、资料范围恢复、半截回复隔离、追问继承、猜错继续和预测取消，使中断与恢复成为完整交互流程的一部分。

### 6.3 页面布局与交互设计

各页面使用统一的视觉语言，同时根据任务区分信息层级。首页突出功能入口，聊天页突出消息与输入，资料页突出导入与来源，预测页按步骤呈现参数和结果，猜心页突出当前问题与回答操作。

| 范围 | 设计内容 |
| --- | --- |
| 主题 | 提供深蓝科技、明亮专业、极光紫、奶油橙、翡翠绿，统一渐变、阴影、高光和语义色 |
| 外壳导航 | 背景光晕、半透明导航、选中胶囊和统一返回按钮 |
| 首页 | 品牌标识、时段问候、开聊面板、功能点缀色和最近对话时间 |
| 聊天 | 角色色头像、品牌气泡、推荐问题卡、引用编号及历史浮层 |
| 问知 | 导入/查找分区、明确的提问按钮、资料卡和原文浮层 |
| 问数 | 步骤编号、演示场景布局、参数标签、灵敏度选择和结果分层 |
| 猜心 | 开局规则、思考状态、三种回答反馈、候选及结算卡 |
| 管理页面 | 角色搜索、主题预览、记忆标签、空状态及锁屏统一 |
| 移动细节 | 长选项完整显示、底部安全留白、触屏操作尺寸、主题化下拉箭头和密码显示按钮 |

### 6.4 视觉原则

CSS 变量统一背景、文字、描边、品牌和成功/警示/危险颜色，使状态色跟随明暗主题变化。动效提示等待、选中和按压，但不替代文字说明。虚拟滚动依赖固定行高，视觉调整需保留其布局契约。

## 8. 运行、构建与部署

### 8.1 本地开发

准备支持当前依赖的 Node.js 与 pnpm，在项目根目录运行：

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

默认访问 `http://localhost:5173`，端口变化时以终端输出为准。手机局域网调试需使用电脑实际局域网地址并允许网络访问。项目未声明 Node.js `engines`，具体版本兼容性需以依赖安装结果验证。

进入“我的”选择厂商、填写自己的 API Key，必要时在高级配置中修改地址和模型名，然后测试连接。预设不是服务可用性承诺，实际以配置后的测试结果为准。问数本地预测不需要模型 API Key。

### 8.2 检查与网页构建

```powershell
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm preview
```

`build` 先执行类型检查，再生成 `dist`。静态托管部署构建产物，不能直接用 `file://` 打开源码入口来代替运行。

Hash 路由和相对构建资源路径有利于静态托管，但当前 Service Worker 注册及预缓存采用 `/sw.js`、`/index.html` 等根路径。部署到 GitHub Pages 仓库子路径时，需要另行适配和验证 PWA 路径。Service Worker 通常要求 HTTPS 或 localhost；不能仅凭文件存在就断言全部离线可用。

### 8.3 Android 构建

需要匹配当前 Capacitor 和 Android Gradle 工程的 Node.js、JDK、Android SDK。工程设置 compile/target SDK 为 36、min SDK 为 24，Gradle Wrapper 为 8.14.3；首次构建需获取相应依赖。

```powershell
pnpm android:sync
pnpm android:build
```

`android:build` 自带网页构建与同步，可直接执行；debug APK 默认输出到 `android/app/build/outputs/apk/debug/`。项目根目录提供 [AI 智囊团 Android 安装包](AI智囊团2.0.apk)。安装和覆盖更新前，应核对签名及目标设备兼容性。
